# TensorRT

Runs models on NVIDIA GPUs through TensorRT, which compiles the model into an
optimized "engine" for your exact GPU. Often faster than [CUDA](cuda.md), but
building the engine can take seconds to minutes, so cache it.

| | |
|---|---|
| Platforms | Windows x64, Linux |
| In the bundled binaries | Windows: yes. Linux: yes *(not verified)* |
| Requirements | everything [CUDA](cuda.md) needs, plus **TensorRT 10.9** for CUDA 12 (the version ONNX Runtime 1.22 is built against) with its `lib` folder on `PATH`, and a model with **fixed input shapes** (see notes) |
| Method | `appendTensorRTProvider([Map<String, String>? options])` |
| How options reach ONNX Runtime | ONNX Runtime's TensorRT V2 options object: created with ORT's defaults, then your map is applied by `UpdateTensorRTProviderOptions`, which rejects unknown keys |
| 1.22 source | keys: [`tensorrt_execution_provider_info.cc`](https://github.com/syntax-syndicate/onnxruntime/blob/v1.22.0/onnxruntime/core/providers/tensorrt/tensorrt_execution_provider_info.cc) · meanings and defaults: [`tensorrt_provider_options.h`](https://github.com/syntax-syndicate/onnxruntime/blob/v1.22.0/include/onnxruntime/core/providers/tensorrt/tensorrt_provider_options.h) |

## Usage

Append CUDA after TensorRT, so operators TensorRT can't handle still run on
the GPU, then CPU last:

```dart
options
  ..appendTensorRTProvider({
    'trt_fp16_enable': '1',
    'trt_engine_cache_enable': '1',
    'trt_engine_cache_path': cacheDir,
  })
  ..appendCudaProvider()
  ..appendCPUProvider(CPUFlags.useArena);
```

## Options

All values are strings; on/off options take `1` or `0`.

### Common

| Key | Default | What it does |
|---|---|---|
| `device_id` | `0` | Which GPU to use. |
| `trt_fp16_enable` | `0` | Allow FP16 precision. Large speed-up on most GPUs, small accuracy loss. |
| `trt_int8_enable` | `0` | Allow INT8 precision. Needs a calibration table. |
| `trt_engine_cache_enable` | `0` | Save built engines to disk and reuse them on the next launch. |
| `trt_engine_cache_path` | working directory | Where engines are cached. |
| `trt_engine_cache_prefix` | none | File name prefix for cached engines. |
| `trt_timing_cache_enable` | `0` | Cache layer timings, which speeds up building new engines. |
| `trt_timing_cache_path` | `trt_engine_cache_path` | Where the timing cache is stored. |
| `trt_force_timing_cache` | `0` | Use the timing cache even if it was made on a different GPU. |
| `trt_max_workspace_size` | `0` (all GPU memory) | Bytes TensorRT may use while building. |
| `trt_builder_optimization_level` | `3` | `0`–`5`. Below `3` builds faster but runs slower. |
| `trt_cuda_graph_enable` | `0` | Use CUDA graphs inside TensorRT. |

### Precision and calibration

| Key | Default | What it does |
|---|---|---|
| `trt_int8_calibration_table_name` | none | INT8 calibration table file. |
| `trt_int8_use_native_calibration_table` | `0` | Use a table generated by TensorRT itself. |
| `trt_layer_norm_fp32_fallback` | `0` | Keep Pow + Reduce in layer norm in FP32. |
| `trt_sparsity_enable` | `0` | Allow sparse weights. |

### Model partitioning

| Key | Default | What it does |
|---|---|---|
| `trt_max_partition_iterations` | `1000` | Max parser iterations when splitting the model. |
| `trt_min_subgraph_size` | `1` | Smallest subgraph given to TensorRT. |
| `trt_op_types_to_exclude` | none | Operator types never sent to TensorRT. |

### Dynamic shapes

| Key | Default | What it does |
|---|---|---|
| `trt_profile_min_shapes` | none | Smallest input shapes, e.g. `input:1x3x224x224`. |
| `trt_profile_max_shapes` | none | Largest input shapes. |
| `trt_profile_opt_shapes` | none | Shapes to optimize for. |

### Engine build

| Key | Default | What it does |
|---|---|---|
| `trt_force_sequential_engine_build` | `0` | Build engines one at a time. |
| `trt_build_heuristics_enable` | `0` | Use heuristics to build faster. |
| `trt_detailed_build_log` | `0` | Log each build step with timings. |
| `trt_auxiliary_streams` | `-1` (heuristics) | Max auxiliary streams per inference stream; `0` uses the least memory. |
| `trt_tactic_sources` | default | Add (`+`) or remove (`-`) tactic sources. |
| `trt_extra_plugin_lib_paths` | none | Extra TensorRT plugin libraries. |
| `trt_preview_features` | none | Comma-separated TensorRT preview features. |
| `trt_context_memory_sharing_enable` | `0` | Share context memory between subgraphs. |
| `trt_engine_hw_compatible` | `0` | Build engines that work across GPU architectures. |
| `trt_weight_stripped_engine_enable` | `0` | Build engines without weights (smaller cache). |
| `trt_onnx_model_folder_path` | none | Folder of the original model, used to refit weight-stripped engines. |

### Engine decryption and debugging

| Key | Default | What it does |
|---|---|---|
| `trt_engine_decryption_enable` | `0` | Decrypt cached engines when loading. |
| `trt_engine_decryption_lib_path` | none | Library that does the decryption. |
| `trt_dump_subgraphs` | `0` | Dump TensorRT subgraphs for debugging. |
| `trt_dump_ep_context_model` | `0` | Dump an "EP context" model that embeds the engine. |
| `trt_ep_context_file_path` | none | Where to dump it. |
| `trt_ep_context_embed_mode` | `0` | `0` = context holds the engine cache path, `1` = the engine bytes. |
| `trt_dla_enable` | `0` | Use the DLA accelerator (Jetson devices). |
| `trt_dla_core` | `0` | Which DLA core. |

Keys that take a memory address (`user_compute_stream`,
`has_user_compute_stream`, `trt_onnx_bytestream`, `trt_onnx_bytestream_size`)
can't be used from Dart.

## Notes

- **Models need known shapes.** TensorRT rejects models whose intermediate
  shapes aren't known up front. The example's VAD model fails with
  *"TensorRT input: … has no shape specified. Please run shape inference on the
  onnx model first"*. Run ONNX Runtime's symbolic shape inference on such
  models before shipping them, or use CUDA for them.
- **That failure comes when the session is created**, not when you append
  the provider: `appendTensorRTProvider` succeeds, then `OrtSession.fromBuffer`
  / `fromFile` throws. Put session creation inside your `try` if you fall back
  to another provider.
- **Tested** on Windows with an RTX 4070 Laptop GPU and TensorRT 10.9
  (`test/gpu_test.dart`): every key above is accepted and keeps the value you
  set, FP32 and FP16 results match the CPU provider on an MNIST model, and the
  engine cache is written to `trt_engine_cache_path`.
- The first run with a new model or new shapes builds the engine and can be
  very slow. Enable `trt_engine_cache_enable` so later launches skip it.
- **"…depends on nvinfer_10.dll which is missing"**: TensorRT isn't installed
  or isn't on `PATH`.
- Before #4 the plugin used TensorRT's old V1 options and turned on FP16,
  engine caching and subgraph dumping by itself. Pass
  `'trt_fp16_enable': '1', 'trt_engine_cache_enable': '1'` to keep that.
